## ⚙️ Python Programs

A Python program is a sequence of **definitions** and **commands** that are evaluated and executed by the **Python interpreter**.

- **Definitions** are evaluated.
- **Commands (statements)** are executed.

### Commands

Commands instruct the interpreter to perform an action. They can be:

- Typed directly into the Python shell.
- Stored in a Python file and executed by the interpreter.

### Comments

Comments are ignored by the Python interpreter and exist to make code readable for humans.

```python
# This is a single-line comment

x = 10  # Inline comment after a statement
```

> [!TIP]
> Write comments to explain **why** something is done, not **what** is done. The code itself should be clear enough to show the "what."

## 🐍 Important Python Fundamentals

> [!IMPORTANT]
> ### Key Points
> 1. **Python is dynamically typed.**
>    - You **do not need to declare the data type** of a variable explicitly.
>    - Python automatically determines the type based on the assigned value.
>    - A variable can **change type** at runtime by reassigning it:
>      ```python
>      x = 5        # x is an int
>      x = "hello"  # x is now a str — no error
>      ```
>
> 2. **Python is case-sensitive.**
>    - Variable names with different letter cases are treated as different variables.
>    - Example:
>      ```python
>      age = 20
>      Age = 30
>      print(age)  # 20
>      print(Age)  # 30
>      ```
>
> 3. **Indentation is mandatory in Python.**
>    - Indentation defines code blocks (instead of braces `{}`).
>    - The standard convention is **4 spaces** per indentation level (PEP 8).
>    - Example:
>      ```python
>      if age >= 18:
>          print("Adult")
>      ```
>
> 4. **Keywords are reserved words.**
>    - Keywords have predefined meanings in Python and **cannot be used as variable names**.
>    - Examples:
>      ```text
>      if      for      while    else     class
>      in      True     False    None     def
>      return  import
>      ```

## 📊 Built-in Data Types

| Type | Description | Example |
| :--- | :--- | :--- |
| `int` | Represents integers | `5`, `-100` |
| `float` | Represents real numbers | `3.27`, `2.0` |

## 🔍 Checking an Object's Type

Use the `type()` function to determine the **exact** type of an object.

```python
type(1234)  # <class 'int'>
type(8.99)  # <class 'float'>
type(True)  # <class 'bool'>
```

### `isinstance()` — Preferred Type Checking

Use `isinstance()` to check if an object is of a given type (or a subclass of it). This is the **Pythonic way** to check types.

```python
x = 5
print(isinstance(x, int))    # True
print(isinstance(x, float))  # False
print(isinstance(True, int)) # True (bool is a subclass of int)
```

| Function | Checks | Considers Inheritance |
| :--- | :--- | :---: |
| `type(x) == int` | Exact type only | ❌ |
| `isinstance(x, int)` | Type **and** subclasses | ✅ |

## 🔄 Type Conversion & Type Casting

### 1. Implicit Type Conversion (Automatic)
- Done **automatically by Python**.
- Occurs when compatible data types are used together.

```python
a = 5
b = 3.0
print(a + b)   # 8.0 (Python converts int to float automatically)
```

---

### 2. Type Casting (Explicit)
- Done **manually by the programmer** using built-in functions.

```python
x = 10

float(x)   # 10.0
str(x)     # "10"
```

#### Common Type Casting Functions
- `int()` — Truncates floats (does **not** round): `int(3.9)` → `3`
- `float()` — Converts to decimal: `float("3.14")` → `3.14`
- `str()` — Converts anything to string: `str(42)` → `"42"`
- `bool()` — Converts to Boolean based on truthiness
- `tuple()` — Converts iterable to tuple

> [!WARNING]
> Invalid conversions raise a `ValueError`:
> ```python
> int("hello")  # ValueError: invalid literal for int()
> float("abc")  # ValueError: could not convert string to float
> ```
> Always validate input before casting, especially with `input()`.

## ➕ Python Operators

Operators perform operations on objects and produce a new value.

### Arithmetic Operators

| Operator | Description | Example | Result |
| :---: | :--- | :--- | :--- |
| `+` | Addition | `i + j` | Sum of `i` and `j` |
| `-` | Subtraction | `i - j` | Difference between `i` and `j` |
| `*` | Multiplication | `i * j` | Product of `i` and `j` |
| `/` | Division | `i / j` | Always returns a `float` |
| `//` | Floor Division | `i // j` | Quotient rounded **toward −∞** |
| `%` | Modulus | `i % j` | Remainder after division |
| `**` | Exponentiation | `i ** j` | `i` raised to the power `j` |

> [!WARNING]
> **Floor Division Gotcha with Negative Numbers**
>
> `//` rounds toward **negative infinity**, not toward zero:
> ```python
> 7 // 2     #  3  (as expected)
> -7 // 2    # -4  (not -3 — rounds down toward −∞)
> ```
> This catches many programmers off guard. Use `int(-7 / 2)` if you want truncation toward zero (`-3`).

> [!NOTE]
> **`**` is right-associative** — it evaluates from right to left:
> ```python
> 2 ** 3 ** 2   # = 2 ** (3 ** 2) = 2 ** 9 = 512
> # NOT (2 ** 3) ** 2 = 8 ** 2 = 64
> ```

## ⚡ Operator Precedence in Python

Operator precedence determines the **order in which operations are evaluated**.

### Order of Precedence (Highest → Lowest)

1. `()` → Parentheses
2. `**` → Exponentiation
3. `+x`, `-x`, `~x` → Unary operators
4. `*`, `/`, `//`, `%` → Multiplication, Division, Floor Division, Modulus
5. `+`, `-` → Addition, Subtraction
6. `<<`, `>>` → Bitwise Shift
7. `&` → Bitwise AND
8. `^` → Bitwise XOR
9. `|` → Bitwise OR
10. `<`, `<=`, `>`, `>=`, `!=`, `==` → Comparison
11. `not` → Logical NOT
12. `and` → Logical AND
13. `or` → Logical OR
14. `=`, `+=`, `-=`, `*=`, ... → Assignment (Lowest)

#### Example

```python
x = 10
y = 20
z = 5

print(x > z and y > x)   # True
print(x > y or y > z)    # True
print(not (x > y))       # True
```

> [!NOTE]
> **Unary operators** work on **a single operand** (a single value or variable).
> - `+x` → Unary Plus (indicates a positive value)
> - `-x` → Unary Minus (indicates a negative value)

```python
x = 10

print(+x)   # 10
print(-x)   # -10
```

### How `and` / `or` Actually Return Values

Python's `and` and `or` return **one of the operands**, not necessarily `True` or `False`.

| Expression | Rule | Returns |
| :--- | :--- | :--- |
| `x and y` | If `x` is falsy, return `x`; otherwise return `y` | First falsy or last value |
| `x or y` | If `x` is truthy, return `x`; otherwise return `y` | First truthy or last value |

```python
5 and 10      # 10 (5 is truthy → return second)
0 and 10      # 0  (0 is falsy → return first)
5 or 10       # 5  (5 is truthy → return first)
0 or 10       # 10 (0 is falsy → return second)
"" or "hello" # "hello"
```

> [!TIP]
> **Memory trick**: `and` needs **both** to be truthy, so it keeps going until it finds a falsy value (or reaches the end). `or` needs **one** truthy value, so it stops at the first truthy value.

### Question 4: Short-Circuit Trap ⭐⭐⭐

```python

```

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

## 🏷️ Naming Conventions

### Valid Variable Names

A valid Python variable name must:
- Start with a **letter** (`a-z`, `A-Z`) or **underscore** (`_`)
- Contain only letters, digits (`0-9`), and underscores
- **Not** be a reserved keyword (`if`, `for`, `True`, etc.)

```python
my_var = 10     # ✅ Valid
_private = 5    # ✅ Valid (convention for private variables)
2name = "hi"    # ❌ SyntaxError (starts with a digit)
my-var = 10     # ❌ SyntaxError (contains hyphen)
```

### Naming Styles

| Style | Convention | Used For |
| :--- | :--- | :--- |
| **snake_case** | `my_variable` | Variables, functions (PEP 8 standard) |
| **PascalCase** | `MyClass` | Class names |
| **camelCase** | `myVariable` | Not standard in Python (used in JavaScript) |
| **UPPER_SNAKE** | `MAX_SIZE` | Constants |
