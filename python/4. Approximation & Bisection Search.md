## 🐛 Progressive Debugging: Floating-Point Precision

Before we approximate roots, we must understand how Python handles decimals (`float`).

### ⚠️ The Float Equality Trap

```python
x = 0
for i in range(10):
    x += 0.1

print(x == 1)
print(x, "==", 10 * 0.1)
```

**Output**

```text
False
0.9999999999999999 == 1.0
```

> [!WARNING]
> **Never use `==` to compare floating-point numbers.**
> Internally, Python uses IEEE 754 floating-point arithmetic. Numbers like `0.1` cannot be represented perfectly in binary, leading to tiny rounding errors.

### The Fix: Epsilon Tolerance

Instead of strict equality, check if the **absolute difference** is within a tiny tolerance (**epsilon**):

```python
epsilon = 1e-6 # 0.000001
x = 0.1 + 0.2

if abs(x - 0.3) < epsilon:
    print("Close enough to be considered equal!")
```

## 🎯 Exhaustive Approximation Algorithm

Approximation means finding an answer that is **close enough** instead of exact.

### Goal

Find the square root of `x` such that:
$$|guess^2 - x| < epsilon$$

where **epsilon** is a very small error value.

### Approximation Algorithm

1. Start with a small guess.
2. Increase the guess by a tiny amount.
3. Check if `guess²` is close enough to `x`.
4. Stop when the error is smaller than `epsilon`.

### Implementation

```python
x = 36
epsilon = 0.01
guess = 0.0
increment = 0.0001
num_guesses = 0

while abs(guess**2 - x) >= epsilon:
    guess += increment
    num_guesses += 1

print("num_guesses =", num_guesses)
print(guess, "is close to square root of", x)
```

### Why Doesn't It Work for Large Numbers?

Example:
```python
x = 54321
```

Using
```python
increment = 0.0001
```

the program must perform **millions of iterations** before reaching the square root (≈233.07).

This makes the algorithm **extremely slow** ($\mathcal{O}(N)$).

To avoid an infinite loop, we add another condition:
```python
guess**2 <= x
```

### Improved Implementation

```python
x = 54321
epsilon = 0.01
guess = 0.0
increment = 0.0001
num_guesses = 0

while abs(guess**2 - x) >= epsilon and guess**2 <= x:
    guess += increment
    num_guesses += 1

print("num_guesses =", num_guesses)

if abs(guess**2 - x) >= epsilon:
    print("Failed on square root of", x)
else:
    print(guess, "is close to square root of", x)
```

> [!TIP]
> Approximation using small increments is simple but **very inefficient** for large numbers. Algorithms like **bisection search** and **Newton's method** are much faster.

## 🔍 Bisection Search

**Bisection Search** is a search technique used when search spaces are **ordered**. By repeatedly **halving the search interval**, it eliminates 50% of the remaining search space at every step ($\mathcal{O}(\log_2 N)$).

### Algorithm Steps

1. Set `low = 0` and `high = x`.
2. Calculate `guess = (low + high) / 2`.
3. If `guess²` is too small, move `low = guess`.
4. Otherwise, move `high = guess`.
5. Repeat until $|guess^2 - x| < \epsilon$.

### Python Implementation

```python
x = 54321
epsilon = 0.01

low = 0
high = x

guess = (low + high) / 2
num_guesses = 0

while abs(guess**2 - x) >= epsilon:
    if guess**2 < x:
        low = guess
    else:
        high = guess

    guess = (low + high) / 2
    num_guesses += 1

print("num_guesses =", num_guesses)
print(guess, "is close to square root of", x)
```

> [!NOTE]
> Bisection search finds the square root of 54,321 in about **30 steps**, compared to millions for exhaustive approximation!

### Edge Case: $0 < x < 1$

For $x = 0.25$, $\sqrt{0.25} = 0.5$. Notice that `0.5` is **greater** than `0.25`.
If we set our upper bound (`high`) to `x`, bisection search will fail because the answer is outside the bounds!

**Fix**: If $x < 1$, set `high = 1.0`.

```python
x = 0.5
high = x if x >= 1 else 1.0
```

## ⚡ Newton-Raphson Method

The **Newton-Raphson Method** is an iterative root-finding algorithm that uses the **derivative (slope)** of a function to rapidly converge to a root where $f(x) = 0$.

### Derivation for Square Root

To find $\sqrt{k}$, define $p(x) = x^2 - k = 0$.

Derivative:
$$p'(x) = 2x$$

Newton-Raphson update formula:
$$g_{\text{next}} = g - \frac{p(g)}{p'(g)} = g - \frac{g^2 - k}{2g}$$

![Newton-Raphson Method](Pasted%20image%2020260725220204.png)

### Python Implementation

```python
epsilon = 0.01
k = 24.0

guess = k / 2.0  # Initial guess
num_guesses = 0

while abs(guess**2 - k) >= epsilon:
    guess = guess - ((guess**2 - k) / (2 * guess))
    num_guesses += 1

print("num_guesses =", num_guesses)
print("Square root of", k, "is about", guess)
```

> [!TIP]
> Newton-Raphson has **quadratic convergence** — the number of correct digits roughly doubles with every step, making it even faster than bisection search.

### Example: Finding the Cube Root

Find a value `g` such that:
$$f(g, x) = g^3 - x = 0$$

Newton's Method computes a better approximation using the formula:
$$g_{\text{next}} = g - \frac{f(g)}{f'(g)}$$

For the cube root function, the next guess becomes:
$$g_{\text{next}} = g - \frac{g^3 - x}{3g^2}$$

```python
# Try Newton-Raphson for cube root

x = int(input("What x to find the cube root of? "))
g = int(input("What guess to start with? "))

print("Current estimate cubed =", g**3)

next_g = g - ((g**3 - x) / (3 * g**2))

print("Next guess to try =", next_g)
```

> [!NOTE]
> The code above shows **one single Newton-Raphson step** to verify the formula. In practice, you wrap it in a `while` loop just like bisection search — keep applying the update until `abs(g**3 - x) < epsilon`.

### Question 1: The Float Equality Trap 🐛 (Debugging)

Why does this code print `False`?

```python
print(0.1 + 0.2 == 0.3)
```

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution & Explanation

Because of binary floating-point representation, `0.1 + 0.2` evaluates to `0.30000000000000004`, which is not strictly equal to `0.3`. You must always use an epsilon tolerance to compare floats!

</details>

### Question 2: Bisection Bound Error 🔥 (Edge Case)

If you are using bisection search to find the cube root of a negative number (e.g., `x = -27`), what happens if you initialize `low = 0` and `high = x`?

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution

The search space is invalid because `low (0)` is mathematically greater than `high (-27)`.

#### 🔍 Explanation

Bisection search relies on an ordered search space where `low <= high`. To support negative numbers, you must check the sign of `x` and set `low` and `high` appropriately (e.g., `low = x`, `high = 0`).

</details>

### Question 3: The Monotonicity Requirement 💼 (Interview)

Could you use Bisection Search to find the maximum height of a thrown ball (a parabola that goes up, then down)?

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution

No! Bisection search fundamentally requires a **monotonic** search space (meaning it strictly increases or strictly decreases).

#### 🔍 Explanation

If a function goes up and then down, and you evaluate the midpoint, you have no way of knowing whether the target is in the left half or the right half. Bisection search only works when evaluating the midpoint guarantees which half the target resides in.

</details>

### Question 4: The Machine Epsilon Trap 🧠 (HOTS)

A developer wants an incredibly precise answer, so they set `epsilon = 1e-300` (a zero followed by 300 decimal places). What will likely happen when they run their bisection search?

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution

The program will likely enter an **infinite loop**.

#### 🔍 Explanation

Standard 64-bit floating-point numbers can only represent roughly 15-17 significant decimal digits of precision. The gap between two representable floats is known as "machine epsilon." If you set your tolerance smaller than this physical limit, the computer can literally never calculate a `guess` close enough to satisfy the condition, causing the loop to run forever!

</details>

### Question 4.1: Zero Epsilon Trap 💡 (Concept Check)

A developer sets `epsilon = 0` to get a "perfectly exact" answer. What will happen when this runs?
```python
x = 25
epsilon = 0
guess = (0 + x) / 2

while abs(guess**2 - x) >= epsilon:
    if guess**2 < x:
        low = guess
    else:
        high = guess
    guess = (0 + x) / 2
```

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution
The program will run **forever** (infinite loop).

#### 🔍 Explanation
A 64-bit floating-point number has a physical precision limit of about 15–17 decimal digits. This gap between adjacent representable numbers is called **machine epsilon** (~`2.2e-16`). Even for a perfect square like `25`, `guess**2 - x` will never be *exactly* `0` — only extremely close to `0`. The condition `abs(...) >= 0` is almost always `True`, so the loop never exits.

Always set `epsilon` to a small but realistic value like `0.0001` or `1e-10` — never `0`.
</details>

### Question 5: The Halving Power of Bisection 📈 (Advanced)

If you are searching for a number between 1 and 1,000,000, roughly how many guesses will it take bisection search to find the exact number (assuming integers only)?

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution
Only about 20 guesses!

#### 🔍 Explanation
Bisection search eliminates half of the search space with every single guess. The mathematical question is: "How many times can you divide 1,000,000 by 2 until you reach 1?" 
This is the definition of a base-2 logarithm: $\log_2(1,000,000) \approx 19.93$. 
This is why $\mathcal{O}(\log_2 N)$ algorithms are so incredibly powerful—even if the search space grows to 1 **billion**, it would only take about 30 guesses!
</details>

## 📊 Summary of Root-Finding Algorithms

| Method                     | Core Idea                        | Convergence Speed            |
| :------------------------- | :------------------------------- | :--------------------------- |
| **Exhaustive Enumeration** | Check every value                | Slow ($\mathcal{O}(N)$)      |
| **Approximation**          | Small increments                 | Slow ($\mathcal{O}(N)$)      |
| **Bisection Search**       | Halve the search space           | Fast ($\mathcal{O}(\log N)$) |
| **Newton-Raphson**         | Use tangent line (derivative)    | Fastest (Quadratic)          |

### Iterative Algorithms

All these algorithms follow the same pattern:

1. Make an initial guess.
2. Improve the guess.
3. Check if it is close enough.
4. Repeat until the error is less than `epsilon`.

Different algorithms differ **only in how they generate the next guess**:
- Exhaustive Enumeration
- Approximation
- Bisection Search
- Newton-Raphson
