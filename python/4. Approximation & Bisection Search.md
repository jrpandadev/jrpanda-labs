## 🐛 Progressive Debugging: Floating-Point Precision

Before we approximate roots, we must understand how Python handles decimals (`float`).

### ⚠️ The Float Equality Trap

```python
x = 0
for i in range(10):
    x += 0.1

print(x == 1)
print(x, "==", 10 * 0.1)
```

**Output**
```text
False
0.9999999999999999 == 1.0
```

> [!WARNING]
> **Never use `==` to compare floating-point numbers.**
> Internally, Python uses IEEE 754 floating-point arithmetic. Numbers like `0.1` cannot be represented perfectly in binary, leading to tiny rounding errors.

### The Fix: Epsilon Tolerance

Instead of strict equality, check if the **absolute difference** is within a tiny tolerance (**epsilon**):

```python
epsilon = 1e-6 # 0.000001
x = 0.1 + 0.2

if abs(x - 0.3) < epsilon:
    print("Close enough to be considered equal!")
```

## 🎯 Exhaustive Approximation Algorithm

Approximation means finding an answer that is **close enough** within an acceptable error bound ($\epsilon$).

### Goal
Find the square root of `x` such that:
$$|\text{guess}^2 - x| < \epsilon$$

### Implementation
1. Start with a small guess (`0.0`).
2. Increment the guess by a tiny step (`0.0001`).
3. Stop when the error is smaller than $\epsilon$ or when we overshoot `x`.

```python
x = 36
epsilon = 0.01
guess = 0.0
increment = 0.0001
num_guesses = 0

while abs(guess**2 - x) >= epsilon and guess**2 <= x:
    guess += increment
    num_guesses += 1

print("num_guesses =", num_guesses)

if abs(guess**2 - x) >= epsilon:
    print("Failed on square root of", x)
else:
    print(guess, "is close to square root of", x)
```

### Why Exhaustive Approximation Fails for Large Numbers
For $x = 54321$, stepping by `0.0001` requires **millions of iterations**. Exhaustive approximation is simple to write, but computationally **inefficient** ($\mathcal{O}(N)$).

## 🔍 Bisection Search

**Bisection Search** is a search technique used when search spaces are **ordered**. By repeatedly **halving the search interval**, it eliminates 50% of the remaining search space at every step ($\mathcal{O}(\log_2 N)$).

### Algorithm Steps
1. Set `low = 0` and `high = x`.
2. Calculate `guess = (low + high) / 2`.
3. If `guess²` is too small, move `low = guess`.
4. Otherwise, move `high = guess`.
5. Repeat until $|guess^2 - x| < \epsilon$.

### Python Implementation
```python
x = 54321
epsilon = 0.01

low = 0
high = x

guess = (low + high) / 2
num_guesses = 0

while abs(guess**2 - x) >= epsilon:
    if guess**2 < x:
        low = guess
    else:
        high = guess

    guess = (low + high) / 2
    num_guesses += 1

print("num_guesses =", num_guesses)
print(guess, "is close to square root of", x)
```

> [!NOTE]
> Bisection search finds the square root of 54,321 in about **30 steps**, compared to millions for exhaustive approximation!

### Edge Case: $0 < x < 1$
For $x = 0.25$, $\sqrt{0.25} = 0.5$. Notice that `0.5` is **greater** than `0.25`. 
If we set our upper bound (`high`) to `x`, bisection search will fail because the answer is outside the bounds!

**Fix**: If $x < 1$, set `high = 1.0`.

```python
x = 0.5
high = x if x >= 1 else 1.0
```

## ⚡ Newton-Raphson Method

The **Newton-Raphson Method** is an iterative root-finding algorithm that uses the **derivative (slope)** of a function to rapidly converge to a root where $f(x) = 0$.

### Derivation for Square Root
To find $\sqrt{k}$, define $p(x) = x^2 - k = 0$.

Derivative:
$$p'(x) = 2x$$

Newton-Raphson update formula:
$$g_{\text{next}} = g - \frac{p(g)}{p'(g)} = g - \frac{g^2 - k}{2g}$$

![Newton-Raphson Method](Pasted%20image%2020260725220204.png)

### Python Implementation
```python
epsilon = 0.01
k = 24.0

guess = k / 2.0  # Initial guess
num_guesses = 0

while abs(guess**2 - k) >= epsilon:
    guess = guess - ((guess**2 - k) / (2 * guess))
    num_guesses += 1

print("num_guesses =", num_guesses)
print("Square root of", k, "is about", guess)
```

> [!TIP]
> Newton-Raphson has **quadratic convergence** — the number of correct digits roughly doubles with every step, making it even faster than bisection search.

### Question 2: Bisection Bound Error ⭐⭐⭐ (HOTS)

If you are using bisection search to find the cube root of a negative number (e.g., `x = -27`), what happens if you initialize `low = 0` and `high = x`?

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution
The search space is invalid because `low (0)` is greater than `high (-27)`.

#### 🔍 Explanation
Bisection search relies on an ordered search space where `low <= high`. To support negative numbers, you must check the sign of `x` and set `low` and `high` appropriately (e.g., `low = x`, `high = 0`).
</details>

## 🏗️ Real-World Challenge: Dream House Savings – Part C

*(Continued from Module 3...)*

### 📌 Problem Statement
Find the **minimum annual rate of return (`r`)** required to save enough money for the down payment on a dream house in **exactly 36 months (3 years)**. 

Because the relationship between the rate `r` and the final savings is complex, you will use **Bisection Search** to discover the correct rate!

### 🧠 Systematic Problem-Solving Framework

<details>
<summary><b>1. Understand & Break Down</b></summary>

- **Target**: Down payment = **25% of $800,000** = **$200,000**
- **Tolerance**: We want our final savings to be within **$100** of the target. (`epsilon = 100`)
- **Inputs**: Initial deposit (e.g. `$150,000`).
- **Search Space**: The annual return rate `r` can be anywhere between `0.0` (0%) and `1.0` (100%).
- **Formula**: $\text{amount saved} = \text{initial deposit} \times \left(1 + \frac{r}{12}\right)^{36}$

</details>

<details>
<summary><b>2. Implementation (Try it yourself first!)</b></summary>

```python
initial_deposit = float(input("Enter the initial deposit: "))

# Constants
down_payment = 800000 * 0.25
months = 36
epsilon = 100

# Search bounds for rate 'r'
low = 0.0
high = 1.0
steps = 0

while True:
    steps += 1
    r = (low + high) / 2
    
    # Evaluate the guess
    amount_saved = initial_deposit * (1 + r / 12) ** months

    # Did we hit the target?
    if abs(amount_saved - down_payment) <= epsilon:
        break
    
    # Adjust bounds
    if amount_saved < down_payment:
        low = r    # Rate was too low
    else:
        high = r   # Rate was too high

print("Best annual rate of return:", r)
print("Steps in bisection search:", steps)
```
</details>

## 📊 Summary of Root-Finding Algorithms

| Method | Core Idea | Convergence Speed |
| :--- | :--- | :--- |
| **Exhaustive Enumeration** | Advance by tiny steps | Slow ($\mathcal{O}(N)$) |
| **Bisection Search** | Halve search space interval | Fast ($\mathcal{O}(\log N)$) |
| **Newton-Raphson** | Follow tangent line (derivative) | Fastest (Quadratic) |

---

## 🔑 Key Takeaways

| Concept | Key Point |
| :--- | :--- |
| **Float Precision** | Never use `==` for floats — compare with `abs(a - b) < epsilon` |
| **Exhaustive Approx** | Simple but slow; fails for large values |
| **Bisection Search** | Halves the interval each step. Requires `low <= target <= high` |
| **Newton-Raphson** | Uses derivatives for lightning-fast convergence |
| **Edge Cases** | For roots of $0 < x < 1$, the root is $> x$. Adjust upper bounds to `1.0` |
