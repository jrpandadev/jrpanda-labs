## 🔢 Floating-Point Numbers & Precision

### Absolute Value
The `abs()` function returns the **absolute (positive) value** of a number.

```python
num = -10
num = abs(num)
print(num)   # 10
```

---

### ⚠️ Floating-Point Precision Pitfall

```python
x = 0

for i in range(10):
    x += 0.1

print(x == 1)
print(x, "==", 10 * 0.1)
```

**Output**
```text
False
0.9999999999999999 == 1.0
```

### Why does this happen?
- Floating-point numbers are stored in **binary** (base 2).
- Certain decimal fractions (like `0.1`) cannot be represented exactly in binary floating-point.
- Tiny rounding errors accumulate over repeated operations.

> [!NOTE]
> **Analogy**: Just as $\frac{1}{3}$ = 0.333... can't be represented exactly in base 10, $\frac{1}{10}$ = 0.0001100110011... can't be represented exactly in base 2. It's not a Python bug — it's a fundamental property of how computers store numbers (IEEE 754).

> [!WARNING]
> **Never use `==` to compare floating-point numbers.**

Instead, check if the absolute difference is within a tiny tolerance (**epsilon**):

```python
epsilon = 1e-6

if abs(x - 1) < epsilon:
    print("Equal")
```

### `math.isclose()` — The Pythonic Way

Python's `math` module provides a built-in function for float comparison:

```python
import math

print(math.isclose(0.1 + 0.2, 0.3))  # True
```

> [!TIP]
> Prefer `math.isclose()` over manual epsilon checks. It handles relative and absolute tolerances automatically.

## 🎯 Exhaustive Approximation Algorithm

Approximation means finding an answer that is **close enough** within an acceptable error bound ($\epsilon$).

### Goal
Find the square root of `x` such that:
$$|\text{guess}^2 - x| < \epsilon$$

### Algorithm Steps
1. Start with a small guess (e.g., `0.0`).
2. Increment the guess by a tiny step (e.g., `0.0001`).
3. Check if $|\text{guess}^2 - x| < \epsilon$.
4. Stop when the error is smaller than $\epsilon$.

### Implementation
```python
x = 36
epsilon = 0.01
guess = 0.0
increment = 0.0001
num_guesses = 0

while abs(guess**2 - x) >= epsilon:
    guess += increment
    num_guesses += 1

print("num_guesses =", num_guesses)
print(guess, "is close to square root of", x)
```

---

### Why Exhaustive Approximation Fails for Large Numbers
For $x = 54321$, stepping by `0.0001` requires **millions of iterations** before reaching $\sqrt{54321} \approx 233.07$, making the algorithm extremely slow.

To prevent infinite loops when overshooting:

```python
x = 54321
epsilon = 0.01
guess = 0.0
increment = 0.0001
num_guesses = 0

while abs(guess**2 - x) >= epsilon and guess**2 <= x:
    guess += increment
    num_guesses += 1

print("num_guesses =", num_guesses)

if abs(guess**2 - x) >= epsilon:
    print("Failed on square root of", x)
else:
    print(guess, "is close to square root of", x)
```

> [!TIP]
> Exhaustive approximation is simple to write, but **inefficient** for larger values. Algorithms like **bisection search** and **Newton-Raphson** are exponentially faster.

## 🔍 Bisection Search

### What is Bisection Search?
**Bisection Search** is a search technique used when search spaces are **ordered (monotonic)**. By repeatedly **halving the search interval**, it eliminates 50% of the remaining search space at every step.

> [!IMPORTANT]
> Bisection search **only works when the search space is monotonic** (the function consistently increases or decreases). If the function oscillates, bisection may miss the root entirely.

```text
1. Set low = 0 and high = x.
2. Calculate guess = (low + high) / 2.
3. If guess² is too small, move low = guess.
4. Otherwise, move high = guess.
5. Repeat until |guess² - x| < epsilon.
```

### Python Implementation
```python
x = 54321
epsilon = 0.01

low = 0
high = x

guess = (low + high) / 2
num_guesses = 0

while abs(guess**2 - x) >= epsilon:
    if guess**2 < x:
        low = guess
    else:
        high = guess

    guess = (low + high) / 2
    num_guesses += 1

print("num_guesses =", num_guesses)
print(guess, "is close to square root of", x)
```

---

### Efficiency Comparison ($O(N)$ vs $O(\log_2 N)$)

| Search Method | Search Space Reduction | Time Complexity |
| :--- | :--- | :--- |
| **Exhaustive / Linear** | $N, N-1, N-2, \dots$ | $\mathcal{O}(N)$ |
| **Bisection Search** | $N, N/2, N/4, N/8, \dots$ | $\mathcal{O}(\log_2 N)$ |

#### Finding $\sqrt{54321}$

| Method | Number of Guesses |
| :--- | :---: |
| Brute Force | 23,000,000+ |
| Bisection Search | ~30 |

---

### Logarithmic Complexity Proof
At step $k$, the remaining space is $N / 2^k$. When $1$ candidate remains:
$$\frac{N}{2^k} = 1 \implies N = 2^k \implies k = \log_2(N)$$

Thus, time complexity is $\mathcal{O}(\log_2 N)$.

---

### Handling $0 < x < 1$
For $x = 0.5$, $\sqrt{0.5} \approx 0.707$, which lies **outside** $[0, 0.5]$. We adjust the upper search bound to `1.0`:

```python
x = 0.5
epsilon = 0.01

if x >= 1:
    low = 1.0
    high = x
else:
    low = x
    high = 1.0

guess = (low + high) / 2

while abs(guess**2 - x) >= epsilon:
    if guess**2 < x:
        low = guess
    else:
        high = guess

    guess = (low + high) / 2

print(f"{guess} is close to square root of {x}")
```

## ⚡ Newton-Raphson Method

### What is Newton-Raphson?
The **Newton-Raphson Method** is an iterative root-finding algorithm that uses the **derivative (slope)** of a function to rapidly converge to a root where $f(x) = 0$.

### Derivation for Square Root
To find $\sqrt{k}$, define $p(x) = x^2 - k = 0$.

Derivative:
$$p'(x) = 2x$$

Newton-Raphson update formula:
$$g_{\text{next}} = g - \frac{p(g)}{p'(g)} = g - \frac{g^2 - k}{2g}$$

![Newton-Raphson Method](Pasted%20image%2020260725220204.png)

---

### Python Implementation
```python
epsilon = 0.01
k = 24.0

# Initial guess
guess = k / 2.0
num_guesses = 0

while abs(guess * guess - k) >= epsilon:
    num_guesses += 1
    # Newton-Raphson Formula
    guess = guess - ((guess**2 - k) / (2 * guess))

print("num_guesses =", num_guesses)
print("Square root of", k, "is about", guess)
```

---

## 📊 Summary of Root-Finding Algorithms

| Method | Core Idea | Convergence Speed | Convergence Rate |
| :--- | :--- | :--- | :--- |
| **Exhaustive Enumeration** | Check every value | Slow | $\mathcal{O}(N)$ — Linear |
| **Approximation** | Advance by tiny steps | Slow | $\mathcal{O}(N)$ — Linear |
| **Bisection Search** | Halve search space interval | Fast | $\mathcal{O}(\log N)$ — Logarithmic |
| **Newton-Raphson** | Follow tangent line (derivative) | Fastest | Quadratic (doubles correct digits per step) |

---

## 🔑 Key Takeaways

| Concept | Key Point |
| :--- | :--- |
| **Float Precision** | Never use `==` for floats — compare with `abs(a - b) < epsilon` |
| **Exhaustive Approximation** | Simple but $\mathcal{O}(N)$ — fails for large values |
| **Bisection Search** | Halves the interval each step — $\mathcal{O}(\log_2 N)$ |
| **Newton-Raphson** | Uses derivatives for fastest convergence — quadratic convergence |
| **Edge Case: $0 < x < 1$** | Square root exceeds $x$ — adjust search bounds to `[x, 1.0]` |
