## 📦 What is a Tuple?

A **tuple** is an **ordered, immutable** collection of objects.

- Ordered → Elements have a fixed position (index).
- Immutable → Elements cannot be changed after creation.
- Can store objects of different data types.

> [!note]
> Tuples are similar to lists, but unlike lists they are **immutable**. Because of this, tuples are generally **faster** than lists.

### When to Choose a Tuple Over a List

| Situation | Use |
|---|---|
| Data should **never change** (e.g., coordinates, config constants) | **Tuple** |
| Data that changes at runtime (e.g., shopping cart, scores) | **List** |
| Returning **multiple values** from a function | **Tuple** |
| Used as a **dictionary key** | **Tuple** (lists are not hashable!) |
| Iterating over a fixed sequence that won't be modified | **Tuple** (marginally faster) |

## ✏️ Creating Tuples

### Tuple with Multiple Elements

Tuples are typically created by placing elements inside parentheses `()`, separated by commas.

```python
t = (2, "MIT", 3)
```

### Empty Tuple

```python
t = ()
```

### Tuple with One Element

Creating a tuple with a single element requires a trailing comma.

```python
t = (2,)
```

> [!IMPORTANT]
> The comma is required; otherwise Python treats it as a normal value inside parentheses. `t = (2)` is just the integer `2`.

> **🤔 Concept Check: The Singleton Trap**
> ```python
> x = (5)
> y = (5,)
> print(type(x) == type(y))
> ```
> *Prediction:* `False`. `type(x)` is `int`, while `type(y)` is `tuple`. Parentheses alone do not create a tuple—the comma does!

### Tuple Packing (Without Parentheses)

You can also create a tuple without parentheses by simply separating values with commas. This is called **tuple packing**.

```python
t = 10, 20, 30
print(type(t))
```

**Output**

```text
<class 'tuple'>
```

## 🔍 Accessing Elements (Indexing)

Since tuples are ordered, you can access individual elements using their index (starting from `0`).

```python
t = (2, "MIT", 3)

print(t[0])
print(t[1])
```

**Output**

```text
2
MIT
```

You can also use negative indexing to access elements from the end (`-1` is the last element).

```python
print(t[-1])
```

**Output**

```text
3
```

---

## ✂️ Tuple Slicing

You can extract a sub-tuple (a slice) using the `[start:stop:step]` syntax.

```python
t = (10, 20, 30, 40, 50)

print(t[1:4])
print(t[1:2])  # Slicing a single element still returns a tuple
```

**Output**

```text
(20, 30, 40)
(20,)
```

Adding a step:

```python
print(t[0:5:2])
```

**Output**

```text
(10, 30, 50)
```

## ➕ Concatenating and Repeating Tuples

You can join two tuples together using the `+` operator.

```python
t1 = (2, "MIT")
t2 = (3, 5, 6)

new_tuple = t1 + t2

print(new_tuple)
```

**Output**

```text
(2, 'MIT', 3, 5, 6)
```

You can also repeat a tuple using the `*` operator.

```python
print(("A", "B") * 3)
```

**Output**

```text
('A', 'B', 'A', 'B', 'A', 'B')
```

## 🔒 Tuples are Immutable

Once a tuple is created, its elements **cannot** be modified, added, or removed.

```python
t = (2, "MIT", 3)

t[1] = 4
```

**Output**

```text
TypeError: 'tuple' object does not support item assignment
```

> [!WARNING]
> Attempting to assign to a tuple index raises a `TypeError`.

### 🤔 Think Before You Run: The Mutability Illusion

If a tuple is immutable, can we change a list *inside* a tuple?

```python
t = (1, [2, 3])
t[1].append(4)
print(t)
```

<details>
<summary><b>💡 Click to Reveal Answer</b></summary>

**Output:** `(1, [2, 3, 4])`

**Why?** A tuple is an immutable sequence of *references*. The tuple `t` will always point to the integer `1` and the exact same list object. However, the list object itself is **mutable**. We are modifying the list's contents, not the tuple's structure!
</details>

## 🪆 Nested Tuples

Tuples can contain other tuples as elements. This is called nesting.

```python
nested = (1, 2, (3, 4), 5)
```

To access elements inside a nested tuple, you chain the index operators.

```python
print(nested[2])      # Accesses the inner tuple
print(nested[2][0])   # Accesses the first element of the inner tuple
```

**Output**

```text
(3, 4)
3
```

## 🎯 Indexing & Slicing Practice

Given:

```python
seq = (2, 'a', 4, (1, 2))
```

| Expression   | Output          | Why                                  |
| :----------- | :-------------- | :----------------------------------- |
| `len(seq)`   | `4`             | The sequence contains 4 elements     |
| `seq[3]`     | `(1, 2)`        | Element at index 3 is a nested tuple |
| `seq[-1]`    | `(1, 2)`        | Last element (same as index 3)       |
| `seq[3][0]`  | `1`             | First element of the nested tuple    |
| `seq[4]`     | `IndexError`    | Index out of range                   |
| `seq[1]`     | `'a'`           | Element at index 1                   |
| `seq[-2:]`   | `(4, (1, 2))`   | Last two elements                    |
| `seq[1:4:2]` | `('a', (1, 2))` | Indices 1 and 3 (step of 2)          |
| `seq[:-1]`   | `(2, 'a', 4)`   | All except the last element          |
| `seq[1:3]`   | `('a', 4)`      | Elements at indices 1 and 2          |

> [!TIP]
> When working with nested tuples, chain the index operators to drill into inner elements: `seq[3][0]` accesses the first item inside the tuple at position 3.

## 🧰 Built-in Functions & Methods

Python provides several built-in functions that work well with tuples.

| Function   | Description                | Example             | Result      |
| :--------- | :------------------------- | :------------------ | :---------- |
| `len()`    | Number of elements         | `len((1, 2, 3))`    | `3`         |
| `max()`    | Largest element            | `max((3, 5, 0))`    | `5`         |
| `min()`    | Smallest element           | `min((3, 5, 0))`    | `0`         |
| `sum()`    | Sum of all elements        | `sum((1, 2, 3))`    | `6`         |
| `tuple()`  | Converts iterable to tuple | `tuple("abc")`      | `('a', 'b', 'c')` |

### Tuple Methods

Since tuples are immutable, they only have two specific methods:

- **`index(value)`**: Returns the index of the **first occurrence** of a value.
- **`count(value)`**: Returns the number of times a value appears.

```python
t = (10, 20, 30, 20)

print(t.index(30))
print(t.count(20))
```

**Output**

```text
2
2
```

## 📤 Tuple Unpacking

Just as you can pack values into a tuple, you can **unpack** a tuple into multiple variables in a single line.

```python
t = (10, 20, 30)
a, b, c = t

print(a)
print(b)
print(c)
```

**Output**

```text
10
20
30
```

> [!WARNING]
> The number of variables on the left must **exactly match** the number of elements in the tuple. Otherwise, Python raises a `ValueError`.
>
> ```python
> x, y = (1, 2, 3)  # ValueError: too many values to unpack (expected 2)
> ```

This is an incredibly powerful feature when dealing with structured data!

## 🔀 Swapping Variables

Because of tuple packing and unpacking, Python makes swapping values incredibly easy. It creates a tuple on the right side and immediately unpacks it into the variables on the left.

```python
x = 10
y = 20

# Swapping using tuple packing and unpacking
x, y = y, x

print(x, y)
```

**Output**

```text
20 10
```

## ⭐ Extended Unpacking with `*`

When unpacking a tuple, you can use `*` to collect the **remaining elements** into a list.

```python
t = (1, 2, 3, 4, 5)

first, *rest = t
print(first)  # 1
print(rest)   # [2, 3, 4, 5]

first, *middle, last = t
print(first)   # 1
print(middle)  # [2, 3, 4]
print(last)    # 5
```

> [!NOTE]
> The `*` in extended unpacking collects into a **list**, not a tuple, even when unpacking from a tuple.

## 🔗 `zip()` — Pairing Sequences as Tuples

`zip()` takes two or more iterables and combines them **element-by-element** into an iterator of tuples.

```python
names  = ("Alice", "Bob", "Charlie")
scores = (95, 82, 78)

for name, score in zip(names, scores):
    print(f"{name}: {score}")
```

**Output:**
```text
Alice: 95
Bob: 82
Charlie: 78
```

### Key Behaviors of `zip()`
- `zip()` stops at the **shortest** iterable.
- To convert the result to a tuple of tuples: `tuple(zip(names, scores))`.

```python
# zip stops at the shortest — the 'w' is dropped
a = (1, 2, 3)
b = ("x", "y", "z", "w")  # longer!
print(tuple(zip(a, b)))   # ((1, 'x'), (2, 'y'), (3, 'z'))
```

> [!NOTE]
> If you need to pair **all** elements (filling shorter iterables with a placeholder), use `itertools.zip_longest()` from Python's built-in `itertools` module. But for the typical case, `zip()` is the correct tool.

> [!TIP]
> `zip()` is the Pythonic way to iterate over multiple parallel sequences simultaneously. It is far more readable than using index-based access with `range(len(...))`.

## ↩️ Returning Multiple Values

A function can return multiple values by returning a tuple (packing). The caller can then unpack those values into variables.

```python
def quotient_and_remainder(x, y):
    q = x // y
    r = x % y
    return q, r  # Returns a tuple (packing)
```

Calling the function and unpacking the result:

```python
quot, rem = quotient_and_remainder(10, 3)

print("Quotient:", quot)
print("Remainder:", rem)
```

**Output**

```text
Quotient: 3
Remainder: 1
```

## ⚖️ Tuple Comparison

Tuples can be compared using relational operators (`==`, `!=`, `<`, `>`, `<=`, `>=`). Python compares them **lexicographically** (element by element), similar to how words are ordered in a dictionary.

```python
print((1, 2, 3) < (1, 2, 4))
```

**Output**

```text
True
```

Python checks:
1. `1 == 1` (Move to next)
2. `2 == 2` (Move to next)
3. `3 < 4` (True! Comparison stops here)

## 📦 Variable Number of Arguments (`*args`)

Sometimes we don't know how many arguments a function will receive. Python allows us to use `*args` to collect any number of positional arguments into a single **tuple**.

```python
def mean(*args):
    # args is a tuple containing all passed arguments
    if len(args) == 0:
        return 0
    
    total = sum(args)
    return total / len(args)

print(mean(1, 2, 3, 4, 5, 6))
```

**Output**

```text
3.5
```

> [!NOTE]
> The `*` operator packs all the extra positional arguments into a tuple named `args`. In the example above, `args` becomes `(1, 2, 3, 4, 5, 6)`.

### 🤔 Predict the Output: `*args` vs Tuple
What happens if we pass a single tuple to our `mean` function instead of separate arguments?
```python
my_tuple = (1, 2, 3, 4, 5, 6)
print(mean(my_tuple))
```

<details>
<summary><b>💡 Click to Reveal Answer</b></summary>

**Output:** `TypeError` (or it crashes when trying to `sum()`).

**Why?** Because `mean` expects multiple individual positional arguments. When you pass `my_tuple`, it treats the *entire tuple* as the first positional argument. Inside the function, `args` becomes a tuple containing your tuple: `((1, 2, 3, 4, 5, 6),)`.

**The Fix:** You must *unpack* the tuple when passing it to the function using `*`:
```python
print(mean(*my_tuple)) # Outputs 3.5
```
</details>

### Question 2: Tuple Concatenation vs Immutability 💼 (Interview)

What happens when you run this code? Does it violate tuple immutability?
```python
t1 = (1, 2)
t2 = (3, 4)
t1 = t1 + t2
print(t1)
```

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution
```text
(1, 2, 3, 4)
```

#### 🔍 Explanation
Wait, isn't a tuple immutable? Yes! We are not modifying the original tuple `(1, 2)`. Instead, `t1 + t2` creates a **brand new tuple** `(1, 2, 3, 4)`, and we assign this new tuple to the variable `t1`. The original tuple `(1, 2)` is left completely unchanged in memory. This does not violate immutability!
</details>

#### ✅ Solution


#### 🔍 Explanation

### Question 5: The `+=` Mutability Anomaly 🤯 (Advanced)

What happens when you run this code?
```python
t = (1, [2, 3])
try:
    t[1] += [4, 5]
except TypeError:
    print("Caught an error!")
    
print(t)
```

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution
```text
Caught an error!
(1, [2, 3, 4, 5])
```

#### 🔍 Explanation
This is one of Python's most famous edge cases! The `+=` operator on a list does two things:
1. It mutates the list in-place (equivalent to `.extend()`). So `[2, 3]` becomes `[2, 3, 4, 5]`.
2. It attempts to re-assign the new list back to the tuple at index `1` (`t[1] = ...`).

Step 1 succeeds because lists are mutable. Step 2 fails with a `TypeError` because tuples are immutable. The exception is caught, but the list inside the tuple *was actually modified*!
</details>

## 🏗️ Real-World Challenge: Text Analyzer

### Problem

Write a function `char_counts(s)` that returns the number of vowels and consonants as a tuple. Assume the input `s` is a string of lowercase letters without spaces.

```python
char_counts("python")
```

Returns:

- Number of vowels
- Number of consonants

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution

```python
def char_counts(s):
    """
    s is a string of lowercase letters.

    Returns a tuple:
    (number_of_vowels, number_of_consonants)
    """

    vowels = 0
    consonants = 0

    for ch in s:
        if ch in "aeiou":
            vowels += 1
        else:
            consonants += 1

    return vowels, consonants  # Returning multiple values as a tuple (packing)


print(char_counts("python"))
```

**Output**

```text
(1, 5)
```

#### 🔍 Explanation

The function iterates over each character. If it's a vowel (`a, e, i, o, u`), the vowel counter increments; otherwise, the consonant counter increments. Both counts are packed and returned together as a tuple.

</details>

### Part B: Euclidean Distance Tracker

You are writing software for a robotics simulation. You are given a tuple of X-coordinates and a tuple of Y-coordinates representing a robot's path. Calculate the total distance the robot traveled.

*Hint: Use `zip()` to pair the X and Y coordinates, and use the distance formula between consecutive points. Distance = `((x2 - x1)**2 + (y2 - y1)**2)**0.5`*

```python
x_coords = (0, 3, 3)
y_coords = (0, 4, 0)
```

<details>
<summary><b>💡 Click to Reveal Solution & Explanation</b></summary>

#### ✅ Solution

```python
x_coords = (0, 3, 3)
y_coords = (0, 4, 0)

# 1. Combine into a tuple of points: ((0, 0), (3, 4), (3, 0))
points = tuple(zip(x_coords, y_coords))

total_distance = 0

# 2. Iterate through the points, stopping before the last one
for i in range(len(points) - 1):
    # Unpack the current point and the next point
    x1, y1 = points[i]
    x2, y2 = points[i+1]
    
    # Calculate Euclidean distance
    distance = ((x2 - x1)**2 + (y2 - y1)**2) ** 0.5
    total_distance += distance

print(f"Total distance traveled: {total_distance}")
```

**Output**
```text
Total distance traveled: 9.0
```

#### 🔍 Explanation
1. `zip(x_coords, y_coords)` elegantly bundles the independent X and Y sequences into logical `(x, y)` pairs.
2. We iterate up to `len(points) - 1` so we can safely access `points[i+1]` without going out of bounds.
3. We use tuple unpacking (`x1, y1 = points[i]`) to easily grab the values for the math formula.
</details>

## 🔑 Key Takeaways

| Concept                  | Key Point                                                 |
| :----------------------- | :-------------------------------------------------------- |
| **Tuples**               | Ordered, **immutable** collections                        |
| **Single-element tuple** | Requires a trailing comma: `(42,)` not `(42)`             |
| **Indexing & Slicing**   | Same syntax as strings: `t[0]`, `t[1:3]`, `t[::-1]`       |
| **Immutability**         | Cannot assign to indices — `t[0] = 5` raises `TypeError`  |
| **Tuple Packing**        | `t = 1, 2, 3` implicitly creates a tuple                  |
| **Tuple Unpacking**      | `a, b = (1, 2)` assigns each element to a variable        |
| **Extended Unpacking**   | `first, *rest = t` collects remaining elements into a list |
| **Swapping**             | `x, y = y, x` uses tuple packing/unpacking under the hood |
| **Multiple returns**     | Functions can return multiple values packed as a tuple    |
| **`zip()`**              | Pairs elements from multiple iterables into tuples; stops at shortest |
| **`*args`**              | Collects variable positional arguments into a tuple       |
| **Methods**              | Only two available: `.index(val)` and `.count(val)`       |
